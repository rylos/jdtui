# jdtui — core

Rust TUI for JDownloader 2 over the My.JDownloader relay API. Single crate: lib (`src/lib.rs`, all modules `pub`) + bin (`src/main.rs`). ~4k lines, repo github.com/rylos/jdtui.

## Source map (src/)
- `main.rs` — clap `Args` (`--refresh-ms`, `--choose-device`, `--config-path`, `--no-events`, `--no-direct`; global `--json`, `--device`) plus an optional `cli::Command` subcommand: with one, `cli::run` answers and exits and the terminal is never touched; without one, terminal setup (ratatui::init, bracketed paste), event loop: `app.tick()` → `ui::draw` → drain `app.clipboard` (OSC 52, then wl-copy/xclip/xsel) → poll key 50ms → `translate(KeyCode)` → `app.handle_key(Key)`. Ctrl-U/Ctrl-F/Ctrl-A/Ctrl-E, Home/End/Delete are `Key` variants.
- `app.rs` — `App` state + all key handling. `Screen` {Login, Devices, Main}. `Mode` {List, Menu, Properties, Confirm(Action), RemoveChoice, PriorityChoice, VariantChoice, Add, Rename, Directory, NewPackage, ArchivePassword, Filter, FolderChoice, Help, Urls, Accounts, DeviceMenu, About}. `Filter` edits `App.filter` live (rows rebuilt per key; Esc clears marks first, then the filter). `FolderChoice` (Ctrl-F on a "Save to" field) lists folder history + package folders + mounts and returns to `folder_return`. `Add` shows a "Files will go to" preview from `App.folder_policy` (read via `JdApi::folder_policy` when `n` opens) through `model::resolve_folder`. `DeviceMenu` reuses `menu`/`menu_index` with `model::device_menu()`; device actions (`Action::is_device`) skip the selection and go through `run_device_action`. `Mode::About` shows `App.about` (read once via `JdApi::about()` from the `D` menu's first entry, `Action::About`, which returns early in `run_device_action`). `App::report_watched` turns `Update::Watched` into a status message. `HELP` const = key reference (help panel; README table mirrors it). `App::new(config)` auto-signs-in; `App::with_snapshot(snapshot)` = network-free App on Main screen (UI tests + screenshot example).
- `cli.rs` — the non-drawing half: `Command` {Status, Downloads, Grabber, Devices, Start, Stop, Pause, Resume, Add, Watch}. `Status` struct = the flat JSON scripts read (device, device_id, state, running, paused, speed, package counts, bytes, extracting, captchas, grabber_packages, collecting, direct) — its shape is pinned by a test. `connect()` returns `(JdApi, Device)`, picks by `--device` name/id → config `device` → the only one, and applies `set_direct_config`. Never prompts: a script has nobody to ask.
- `watch.rs` — a folder on THIS machine (JD's own FolderWatch covers folders JD can reach). `parse_crawljob` handles both shapes (properties with `->NEW ENTRY<-` and `#`, or JSON) → `Job` → `AddLinks`; containers (dlc/ccf/rsdf) go through `JdApi::add_container`. `sweep()` RETURNS `Vec<Outcome>` and never prints (the TUI would be drawn over); `report()` prints for the CLI. A file is CLAIMED BY MOVING IT FIRST (never send-then-move: that double-sends if the move fails, and on Windows the move fails for exactly the file still held open), then `processed/` or `failed/`. Cross-platform: CRLF, UTF-8 BOM, UTF-16 LE/BE, dotfiles and macOS `._` twins skipped, `SETTLE` 2 s of stillness.
- `ui.rs` — pure drawing, `draw(frame, &App)`. Side panels (menu, remove/priority choice, properties) on the right; popups (forms, help, urls, accounts, about) centered. `status_span`/`status_style` colour by STATE, never by JD's localized words (green done, cyan moving, yellow waiting/extracting, red failed, grey disabled); `eta_seconds(raw, extracting, running)` — JD counts a download's eta in SECONDS and an extraction's in MILLISECONDS, and a row that is neither shows none. Help panel is 2 columns ≥120 cols, drops blank lines when height is short.
- `model.rs` — view model: `Tab`, `Row`/`RowKey`, `build_rows`, `Extraction` {Queued, Running, Done, Failed} + `extraction_of(packages, row, queue)` (language-independent; Done gated on `package.is_finished()`), `Action` enum, `context_menu(tab, packages, rows, stop_mark)`, `Form`/`Field` constructors (login, add_links, rename, directory, new_package, archive_password, filter), `Form::set_value`/`active_label`, `PRIORITIES`, `stop_mark_target`/`row_stop_marked`, `resolve_folder`, `device_menu(update_available, captchas)`.
- `api.rs` — `JdApi` device calls; data types `Package`, `Link` (with `variants`/`variant`), `LinkVariant`, `Snapshot`, `Status`, `RemoveMode`, `AddLinks`, `ArchiveStatus` (incl. `states`: member file name → COMPLETE/INCOMPLETE/MISSING, which is how the queue is matched to a package), `CaptchaJob`, `Account`, `Event`, `FolderPolicy`, `StorageInfo`, `SystemInfo`, `About`. All derive `Serialize` too, for `--json`. `about()` = 6 round trips for the About panel; `add_container(kind, bytes)` sends a base64 data URL. `status()` = slow part (stop mark, collecting, extraction queue, captchas); `snapshot(status)` = state, speed, downloads, grabber (4 round trips, ~110 ms each via relay).
- `myjd.rs` — native My.JDownloader protocol + crypto; own `Error` with `is_auth_failure`/`is_session_expired`.
- `poller.rs` — refresh thread: `status()` every `STATUS_EVERY` (5) refreshes or after a wake, `snapshot()` every refresh. Listener thread (`listen`): own `MyJd` session (listen blocks 25 s), `subscribe_events` with `JdApi::EVENT_SUBSCRIPTIONS` regexes, any event → wake (debounced by `WAKE_GAP` 500 ms, NOT period-relative). With the channel up and state not running the period stretches to `IDLE_PERIOD` (30 s). `Update::Watched(Vec<watch::Outcome>)` when the configured folder yielded something (swept from the refresh thread under the same lock, before the snapshot; a failing folder complains once, not once a second; `WATCH_PERIOD` caps the idle stretch at 5 s while watching). `Update::Events(bool)` → `App.events_live` ("· live" in header). `Poller::set_device` resubscribes (takes up to one poll timeout to notice). Off with config `events = false` / `--no-events`. Both threads call `JdApi::ensure_direct(extra)` (refresh thread before each refresh, listener after (re)subscribing) when `Direct` is Some; `Snapshot.direct: Option<String>` → header "· ⇄ direct" / "· ☁ relay" (ui.rs, shown once a snapshot is in; screenshots demo sets it).
- `config.rs` — `~/.config/jdtui/config.toml`, mode 0600. Keys: email, password, device, refresh_ms, events, direct (bool, default true), direct_addresses, watch_folder, watch (bool, default true → `Config::watch_folder()` gives `None` when off). NOTE: `Config::save` rewrites the file and LOSES COMMENTS. The last is `DirectAddresses` (serde untagged): a plain `["host:port"]` list for every device, or a `[direct_addresses]` table keyed by DEVICE NAME. `Config::direct_for(device_name)` → `Option<Vec<String>>` (None = relay only) = `poller::Direct`. Addresses belong to a machine, so they must never be tried for another device: `JdApi::set_device` clears `direct_extra`, and `app::select_device` calls `set_direct_config` on both paths plus `Poller::set_device(id, direct)` which retargets the listener.

## Other dirs
- `examples/screenshots.rs` — draws real frames into ratatui `TestBackend` → `docs/*.svg` + PNG (rsvg-convert + pngquant, both installed). Data is invented.
- `docs/` — screenshots (incl. `about.png`) + `announcement.txt` (draft community post).
- `config.example.toml` — every key documented; a unit test parses it so it cannot drift from the code.

## Invariants
- Network only in `myjd.rs`/`api.rs`/`poller.rs`; `ui.rs` and `model.rs` never touch it. Keep ui a function of `&App`.
- Destructive actions (`MenuEntry.confirm`, `RemoveMode::touches_files`, `Action::ClearGrabber`) go through `Mode::Confirm` / `Mode::RemoveChoice` first.
- Actions: `run_action` → `with_api` → `finish` (message, clears marks, `refresh_now`). Actions that are not selection actions (stop mark, archive password) save/restore `marked` around `finish`.
- Popup forms all share `self.form` + `handle_form_key`, dispatching on `Mode` at Enter. `Field` text fields keep a char-index `cursor` (insert/backspace/delete/clear are `Field` methods; `Form::cycle` moves it on text fields, cycles choices/flips flags otherwise). Prefill with `Field::with_text` so the cursor lands at the end.
- Keys reach the app only through `Key` (app.rs) translated in `main.rs::translate`; a new physical key (Home, Delete, Ctrl-x…) needs a `Key` variant plus a `translate` arm.
- API quirks worth remembering are in `mem:api_quirks`.

See `mem:tech_stack`, `mem:conventions`, `mem:suggested_commands` (incl. live tests), `mem:task_completion`.
